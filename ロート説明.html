📦 ロートテーブル (Loot Table) の仕組みと構造

ロートテーブルは、Minecraft内で「アイテムがドロップする」状況全てを制御する設計図です。ブロック破壊、エンティティ討伐、チェストの生成など、すべてのランダムなアイテム取得に関わります。

1. ロートテーブルの基本構造

ロートテーブルのJSONファイルは、基本的に複数の **Pools (プール)** から構成されます。全てのドロップは、これらのプールによって定義されます。

{
  "pools": [
    { /* Pool 1 の定義 */ },
    { /* Pool 2 の定義 */ }
  ]
}

2. Pool (プール) とは？

プールは、**ドロップの試行回数 (Rolls)** と、**ドロップの候補リスト (Entries)** を定義する、ドロップの「規則」の単位です。

2.1. Rolls (試行回数)

プール内のアイテムを、何回ドロップさせるかを決めます。これが「ロトを回す回数」にあたります。

例: 試行回数をランダムに設定

"rolls": { "min": 1, "max": 3 }

→ このプール内のドロップ候補から、**1回から3回**アイテムを選び出します。

ブロック破壊時などに、「鉄インゴットが1回出るか、2回出るか」といった判定を制御します。

2.2. Entries (エントリー)

ロールの結果、ドロップするアイテムの具体的な候補リストです。アイテムのID、ドロップ確率、数量などを設定します。

主な設定項目:

  • name: アイテムID (例: minecraft:diamond)
  • weight: ドロップ確率の重み。この値が高いほど選ばれやすくなります。
  • functions: 数量の指定やエンチャント付与など、アイテムに処理を加えるための機能（後述）。

3. Entries 内の重要要素: Weight と Functions

3.1. Weight (重み)

ドロップ確率を制御します。同じプール内のエントリー全ての weight を合算し、その合計値に対する割合でドロップ確率が決まります。

アイテムWeight確率 (合計10の場合)
ダイヤモンド110%
エメラルド330%
石炭660%

Rollsの試行回数ごとに、この比率でアイテムが選ばれます。

3.2. Functions (機能)

ドロップしたアイテムの属性を操作します。最も重要な機能は set_count (数量設定) です。

例: 数量をランダムに設定

"functions": [
  {
    "function": "set_count",
    "count": { "min": 2, "max": 5 } 
  }
]

→ 選ばれたアイテムは、**2個から5個**の間でランダムな数量になります。

他に、エンチャント付与 (enchant_with_levels) やデータ値の設定 (set_data) などがあります。

4. まとめ

ロートテーブルは、以下の構造で動いています。

ロートテーブル全体 → 複数定義された Pools (規則) を実行

Pool (規則) → Rolls (試行回数) だけ Entries (候補) からアイテムを選択

Entry (候補) → weight に基づいて選ばれ、functions で数量や属性が決定
